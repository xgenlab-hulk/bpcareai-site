# Article SEO/GEO Holistic Optimization Guide v2.0
## With Built-in Quality Control & Self-Evaluation (Flexible Judgment)

## Mission

Optimize all SEO/GEO elements of an article in a SINGLE PASS with **guaranteed quality through self-evaluation**.

**Critical Requirement**: You MUST achieve an Overall Quality Score of **85+** before outputting results. If first attempt fails, iterate up to 3 times.

**Core Philosophy**: Use JUDGMENT, not rigid rules. Evaluate quality holistically based on user search behavior and content context.

---

## Workflow Overview

```
1. Read Article → Analyze
2. Generate Optimizations (Attempt 1)
3. Self-Evaluate → Score each element using JUDGMENT
4. Calculate Overall Quality Score
5. If Score >= 85 → Output ✅
   If Score < 85 → Improve (Attempt 2, max 3 attempts)
6. Output best result with quality scores
```

---

## Step 1: Article Analysis

### Read and Understand
1. Read full article content (first 800-1000 words minimum)
2. Identify:
   - **Core medical topic** (specific, not "health/wellness")
   - **Target audience** (age, demographic if relevant)
   - **User search intent** (what users want to know)
   - **Key value proposition** (main benefit)
   - **Target audience knowledge level** (do they know medical terms?)

## Step 2: Generate Optimizations

### 2.1 Slug Optimization

**Scoring Criteria (Total: 100 points) - Use Flexible Judgment**

#### 1. Conciseness & Clarity (40 points)
**Question**: Is the slug short enough to be memorable while clear enough to understand?

**Scoring Guidance** (not rigid rules):
- **Excellent (35-40 pts)**: Very concise (typically 3-5 words), instantly clear what article is about
- **Good (25-34 pts)**: Reasonably short (6-7 words), clear enough
- **Fair (15-24 pts)**: Somewhat long (8-10 words), but still understandable
- **Poor (0-14 pts)**: Too long (11+ words) or confusing structure

**Examples**:
```
✅ "blood-pressure-monitoring-seniors" (4 words) → 40pts
✅ "diabetes-holiday-meal-planning" (4 words) → 38pts
✅ "heart-health-tips-seniors-winter" (5 words) → 35pts
⚠️ "managing-blood-pressure-naturally-at-home-for-seniors" (7 words) → 28pts (workable but long)
❌ "how-to-manage-your-blood-pressure-at-home-naturally-without-medication" (11 words) → 10pts
```

**Note**: There's no hard cutoff. Use judgment about readability.

#### 2. Specific Medical Topic (40 points)
**Question**: Does it indicate a SPECIFIC medical topic users care about?

**Scoring Guidance**:
- **Excellent (35-40 pts)**: Very specific medical topic (e.g., "blood-pressure", "diabetes-diet", "atrial-fibrillation")
- **Good (25-34 pts)**: Specific but could be more precise (e.g., "heart-health-monitoring")
- **Fair (15-24 pts)**: Somewhat specific with context (e.g., "senior-heart-health-winter")
- **Poor (0-14 pts)**: Too vague/generic as MAIN topic (e.g., "health-tips", "wellness-advice")

**Context Matters**:
```
✅ "mental-health-dementia-caregivers" → 38pts (specific even with "health")
❌ "general-health-tips-seniors" → 10pts (generic main topic)
```

#### 3. User-Friendly Language (20 points)
**Question**: Would users understand this terminology?

**Use Judgment**:
- Medical terms patients KNOW are OK: "diabetes", "blood-pressure", "afib", "cholesterol"
- Technical terms patients DON'T know should be avoided: "tmao", "baroreceptor", "endothelial-dysfunction"
- Context matters: "HFpEF" might be OK if audience is heart failure patients

**Scoring**:
- **20 pts**: All terms are user-searchable
- **10-15 pts**: Mostly user-friendly, one borderline term
- **0-9 pts**: Multiple technical terms users won't search

**Minimum Passing Score**: 75/100

**No Auto-Fail Conditions** - Everything is judgment-based

### 2.2 Title Optimization

**Scoring Criteria (Total: 100 points) - Use Flexible Judgment**

#### 1. Includes Core Search Concept (40 points)
**Question**: If someone searched the PrimaryKeyword, would this title be relevant?

**Note**: Don't require EXACT keyword match. Conceptual alignment is enough.

**Examples**:
```
PrimaryKeyword: "blood pressure monitoring seniors"
✅ "Blood Pressure Tips: Home Monitoring Guide for Seniors" → 40pts (conceptually aligned)
✅ "How to Monitor Your BP at Home (Seniors Over 70)" → 38pts (uses "BP" instead of full term, still clear)
⚠️ "Heart Health Monitoring for Elderly Adults" → 25pts (related but not focused on BP)
❌ "General Health Tips for Seniors" → 5pts (too generic, not aligned)
```

#### 2. Length Appropriateness (20 points)
**Question**: Is the length suitable for search results and readability?

**Flexible Range** (not hard cutoffs):
- **Ideal (20 pts)**: 50-65 characters - perfect for search snippets
- **Good (15 pts)**: 40-49 or 66-75 characters - still works well
- **Acceptable (10 pts)**: 76-85 characters - shown with ellipsis but readable
- **Poor (0-5 pts)**: <35 or >90 characters - too short/long

**Example**:
```
"Blood Pressure Monitoring: 7 Tips for Seniors Over 70" (59 chars) → 20pts ✅
"Blood Pressure Management Strategies for Seniors with Diabetes" (64 chars) → 20pts ✅
"Essential Blood Pressure Monitoring Techniques and Best Practices for Seniors Over Age 70" (90 chars) → 5pts ❌
```

#### 3. Clear Value/Benefit (20 points)
**Question**: Is it obvious what value/benefit the user gets?

#### 4. Audience Clarity (10 points)
**Question**: If audience-specific, is it clear who this is for?

**Note**: Only required if content IS audience-specific. Don't force it.

#### 5. Natural & Compelling (10 points)
**Question**: Does it read naturally and compel clicks?

**Minimum Passing Score**: 80/100

**No Auto-Fail Conditions** - Even 80+ chars might be OK if quality is exceptional

---

### 2.3 Description Optimization

**Scoring Criteria (Total: 100 points) - Use Flexible Judgment**

#### 1. Includes Core Search Concept (40 points)
**Question**: Does it naturally include the core concept users are searching for?

**Note**: Don't require exact PrimaryKeyword match. Core concept is enough.

**Examples**:
```
PrimaryKeyword: "diabetes holiday meal planning"
✅ "Plan diabetes-friendly holiday meals that balance blood sugar..." → 40pts (includes concept)
✅ "Holiday eating guide for diabetics. Balance festive foods..." → 38pts (uses "diabetics" vs "diabetes")
⚠️ "Healthy holiday meal ideas for seniors with dietary restrictions..." → 20pts (related but not specific)
```

#### 2. Length Suitability (25 points)
**Question**: Is it the right length for search snippet while being complete?

**Flexible Range**:
- **Ideal (25 pts)**: 145-165 characters
- **Good (20 pts)**: 130-144 or 166-180 characters
- **Acceptable (15 pts)**: 120-129 or 181-200 characters
- **Poor (0-10 pts)**: <110 or >210 characters

**Context Matters**: A 170-char description that's excellent quality beats a mediocre 155-char one.

#### 3. Clear Value Proposition (20 points)
**Question**: Does it clearly explain what the user will get/learn?

#### 4. Complete & Well-Written (10 points)
**Question**: Proper grammar, complete sentences?

#### 5. Action/Benefit Focused (5 points)
**Question**: Does it focus on outcomes rather than just stating facts?

**Minimum Passing Score**: 80/100

**No Auto-Fail Conditions** - Evaluate overall quality, not character count

---

### 2.4 PrimaryKeyword Optimization

**Scoring Criteria (Total: 100 points) - Use v4 Flexible Standard**

#### 1. Real User Search Behavior (40 points)
**Question**: Would real users search using these exact or very similar terms?

**Use Contextual Judgment**:
```
✅ "atrial fibrillation monitoring seniors" → 40pts
   Reasoning: Patients diagnosed with afib know and search this term

✅ "HFpEF symptoms management seniors" → 38pts
   Reasoning: Heart failure patients commonly use this abbreviation

✅ "blood pressure spike morning commute" → 40pts
   Reasoning: Natural way people describe their experience

⚠️ "endothelial dysfunction aging" → 15pts
   Reasoning: General users don't search "endothelial" - they'd search "blood vessel health"

❌ "tmao gut metabolite cardiovascular" → 5pts
   Reasoning: Highly technical, users would search "gut health heart disease"
```

**Key Principle**: Evaluate based on TARGET AUDIENCE knowledge, not general rules.

#### 2. Specificity & Clarity (30 points)
**Question**: Is it specific enough to be useful, but not so niche it's obscure?

**Examples**:
```
✅ "diabetes diet holiday meals" → 30pts (specific + relevant context)
✅ "blood pressure monitoring seniors over 70" → 28pts (very specific audience)
⚠️ "heart health seniors" → 20pts (somewhat specific but broad)
❌ "health tips" → 5pts (way too generic)
```

#### 3. Natural Phrasing (20 points)
**Question**: Does it flow naturally, like how people actually search?

**Good phrasing**:
- "blood pressure monitoring seniors" ✅
- "diabetes holiday meal planning" ✅
- "heart health tips elderly" ✅

**Keyword stuffing**:
- "blood pressure hypertension bp monitoring control seniors" ❌
- "diabetes glucose sugar management diet tips" ❌

#### 4. SEO/GEO Value (10 points)
**Question**: Will this help users find the content?

**Minimum Passing Score**: 85/100

**No Technical Term Blacklist** - Evaluate based on user knowledge for target audience

### 3.2 Calculate Overall Quality Score

```
Overall Score = (Slug × 0.15) + (Title × 0.35) + (Description × 0.25) + (PrimaryKeyword × 0.25)
```

**Weighting Rationale**:
- Title: 35% (most important for CTR and SEO)
- Description: 25% (second most important)
- PrimaryKeyword: 25% (internal use + SEO signal)
- Slug: 15% (less visible but still matters)

**Example**:
```
Overall = (92 × 0.15) + (90 × 0.35) + (88 × 0.25) + (92 × 0.25)
        = 13.8 + 31.5 + 22 + 23
        = 90.3
```

## Step 4: Iteration Logic

### Decision Tree

```
IF Overall Quality Score >= 85 AND All Individual Scores Pass:
   → Output results ✅

ELSE IF Attempt < 3:
   → Identify lowest scoring elements
   → Regenerate those elements with focus on issues
   → Re-evaluate using same flexible judgment
   → Try again

ELSE (Attempt >= 3):
   → Output best attempt
   → Flag as "quality_warning"
   → Explain what couldn't be fixed
```

### What to Improve Each Iteration

**Iteration 2**:
- Focus on elements that scored < 80
- If all scores > 80 but consistency low, align terminology
- Review reasoning for low scores

**Iteration 3**:
- Regenerate ALL elements with stricter focus on top issues
- Ensure strong conceptual alignment
- Maximize user-friendliness

## Critical Principles

### MUST DO
1. ✅ Use JUDGMENT, not mechanical rules
2. ✅ Score every element with clear reasoning
3. ✅ Calculate Overall Quality Score
4. ✅ If score < 85, iterate (max 3 attempts)
5. ✅ Ensure consistency across all elements
6. ✅ Consider target audience knowledge level
7. ✅ Provide detailed reasoning for each score

### MUST NOT DO
1. ❌ Use rigid character/word count cutoffs as auto-fail conditions
2. ❌ Mechanically match keywords from blacklists
3. ❌ Ignore context when evaluating technical terms
4. ❌ Create inconsistent elements (different terminology/audience)
5. ❌ Skip self-evaluation step
6. ❌ Output results below 70 overall score without warnings

---

## Evaluation Philosophy

**Key Mindset Shifts**:

1. **Length is a guideline, not a rule**
   - 60 chars might be perfect for one slug, 65 for another
   - Evaluate: Does the length help or hurt clarity/usability?

2. **"Technical terms" depend on audience**
   - "Atrial fibrillation" is fine - patients know it
   - "Baroreceptor sensitivity" is not - use "blood pressure regulation"
   - Ask: Would MY TARGET AUDIENCE search this term?

3. **Generic terms in context might be OK**
   - "mental-health-tips-caregivers" uses "health" but is specific
   - "general-health-tips" is too vague
   - Evaluate the WHOLE phrase, not just one word

4. **Consistency matters more than perfection**
   - A 78-point slug + 85-point title that align perfectly
   - Beats 95-point slug + 95-point title that contradict each other

5. **User search intent is the north star**
   - Would a real user searching for this topic find this helpful?
   - That's more important than hitting arbitrary metrics
