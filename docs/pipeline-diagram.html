Perplexity Call Details (Line 1)

  • Function: discoverUserQuestions(alert.query)
  • Note: does NOT pass existingTopics here (unlike Line 2)
  • Only top 5 questions used (from up to 15 returned)
  • Questions injected into alertReason string, not separate field
  • On Perplexity failure: continues without questions (empty array)

Urgent Topic Lifecycle

  • Created by: gsc-daily-analysis.ts
  • Consumed by: auto-generate-daily.ts → loadUrgentTopics()
  • TTL: 3 days (expiresAt field)
  • Score filter: only at write time (score >= 50 in gsc-daily-analysis)
  • Read filter: only expiresAt > now (no score filter at read)
  • Field mapping issue: loadUrgentTopics() uses t.query/t.suggestedPK/t.reason instead of t.title/t.primaryKeyword/t.description

No-Alert Path

  • If no alert scores >= 50: cleans expired urgent topics from file
  • Filter: keeps only topics where expiresAt > now
  • Does NOT clear file entirely - preserves valid unexpired topics

Perplexity Call Details (Line 2)

  • Function: discoverUserQuestions(keyword, existingTitles)
  • DOES pass existingTopics (up to 20 articles per keyword)
  • existingTopics filtered by: title includes first word of keyword
  • All 15 questions returned, but only 8 injected as angles
  • Also injects competitorCoverage and whyItMatters as angles

Critical: NO Embedding Dedup

  • Weekly refresh does NOT do embedding-based dedup
  • Topics go straight from LLM generation -> scoring -> library
  • Only text-level dedup: alreadyPlannedTitles passed to LLM prompt
  • Contrast with emergency replenish which DOES do embedding dedup (threshold 0.85)
  • Article-level dedup (0.80) catches duplicates later at generation time

siteInfo Inconsistency

  • LLM deep analysis prompt says: "50+老年人"
  • Perplexity prompt says: "adults (age 35+)"
  • Article generation system prompt says: "adults aged 35 and above"
  • convertUrgentQueryToTopic says: "adults 35+"
  • LLM deep analysis siteInfo should be updated to 35+

Cluster Targets (CLUSTER_TARGETS)

  • lifestyle-interventions: target 200, P1
  • diabetes-management: target 500, P1
  • nutrition-diet-management: target 400, P2
  • cardiovascular-health: target 300, P2
  • hypertension-management: target 600, P3
  • medication-safety: target 150, P3

Word Classification

  • GENERIC_WORDS (not counted as specific): blood, pressure, heart, health, diabetes, sugar, seniors, adults, over, age, high, low, normal
  • STOP_WORDS (ignored entirely): a, an, the, of, for, in, how, does, can, what, etc.
  • Specific words = everything else with length > 2

Trend Detection (for timeliness)

  • Based on 28-day GSC query baseline
  • recent 3d daily avg / total daily avg
  • ratio >= 1.5 = 'up'
  • ratio <= 0.5 = 'down'
  • else = 'stable'

Article Body Generation (Qwen Plus)

  • System role: board-certified cardiologist
  • Target age: adults aged 35 and above
  • 3 random tones: educational/conversational/reassuring
  • Word count always: 1200-1800 (no random range)
  • Required structure sections: H1, Quick Answer, Key Facts (5+), When to See Doctor (4-5 thresholds), H2 Understanding, H2 Actions, H2 Monitoring, Conclusion, FAQ (5 items)
  • GEO rules: PK 4-6x, 3-5 synonyms, AI-quotable paragraphs, medical term bridges, 2+ guideline refs

Metadata Optimization (Qwen Plus)

  • Temperature: 0.3 (low creative, high accuracy)
  • Input: topic fields + first 2000 chars of body
  • PK validation: 15-60 chars, no jargon, --- replaced with —
  • Title validation: 30-70 chars, YAML-safe
  • Description validation: 80-160 chars, no newlines
  • Slug validation: lowercase + digits + hyphens, max 80 chars
  • Cluster: matchTopicCluster() maps to 20 existing clusters

Emergency Replenish Details

  • Trigger: total topics < 30
  • Target: 50 new topics
  • Sort by count ASC (lowest stock first)
  • Per topic single batch: max 20
  • Per topic total cap: 50
  • Dedup: embedding-based, threshold 0.85
  • Includes: extraEmbeddings (newly accepted in same session)
  • Max attempts: 10 rounds per topic
  • Early exit: acceptance rate < 10%
  • Rate limits: 300ms per candidate, 2s between topics

Topic Consumption Logic

  • Both successful AND failed topics are consumed (marked via slugify)
  • Dedup-discarded topics are also consumed
  • Removal: filter planned-topics by slugified title match
  • Urgent topics: removed by suggestedPK match in clearConsumedUrgentTopics()

API Perplexity API - Two Call Sites Comparison

lib/seo/llm-analyzer.ts - discoverUserQuestions() - Same function, different usage contexts

Call Site 1: Daily Urgent (gsc-daily-analysis.ts:239)

  • Trigger: GSC alert with score >= 50
  • Frequency: 0-3 times per day
  • Call: discoverUserQuestions(alert.query)
  • existingTopics: NOT passed (empty default)
  • Questions used: top 5 (from 15 returned)
  • Injection point: Appended to alertReason string for Qwen convertUrgentQueryToTopic()
  • Purpose: Understand what real users ask about the trending query

Call Site 2: Weekly Refresh (weekly-topic-refresh.ts:183)

  • Trigger: Weekly run, for P1 + P2 priority keywords
  • Frequency: 3-4 times per week (P1: cholesterol, diabetes, exercise + P2: healthy eating)
  • Call: discoverUserQuestions(keyword, existingTitles.slice(0,20))
  • existingTopics: PASSED (up to 20 titles per keyword)
  • Questions used: up to 8 injected as angles
  • Injection point: Added to enrichedAngles[] for Qwen generateTopicCandidatesForKeyword()
  • Also injects: competitorCoverage + whyItMatters as angle entries
  • Purpose: Find content gaps and real user needs for topic generation
  • Delay: 500ms between calls

Shared: Perplexity API Config

  • Endpoint: https://api.perplexity.ai/chat/completions
  • Model: sonar
  • Temperature: 0.2
  • System: "health content researcher"
  • Target audience in prompt: "adults (age 35+)"
  • Returns JSON: {questions[15], competitorCoverage, whyItMatters}
  • Graceful failure: returns empty structure, flow continues
  • Auth: PERPLEXITY_API_KEY env var
