# BPCareAI Content Engine — Business Requirements Document

> Version: 1.0 | Date: 2026-04-14 | Author: Hulk

## 1. Executive Summary

BPCareAI Content Engine 是一个**数据驱动的自动化健康内容系统**，目标是通过持续产出高质量的心血管健康文章，建立在 Google 搜索和 AI 搜索引擎（ChatGPT、Perplexity、Gemini）中的内容权威性。

**核心命题**：50岁以上成年人在面对血压、糖尿病、胆固醇等慢性病问题时，会向搜索引擎和 AI 助手提问。我们要成为这些问题的**首选答案来源**——无论是被 Google 展示在搜索结果页，还是被 AI 系统引用在回答中。

**当前规模**：2,209 篇文章，每天自动生成 3 篇，全流程无人值守。

## 2. Problem Statement

### 2.1 用户痛点

50-80岁的中老年人群面临以下困境：

- **信息碎片化**：血压、糖尿病、心脏健康的信息散布在 Mayo Clinic、WebMD、各种论坛中，缺乏针对「特定年龄段 + 特定病况」的精准回答
- **语言壁垒**：医学文献用专业术语写成，患者搜索用自然语言（"Is 140/90 dangerous at 55?"），两者之间存在巨大鸿沟
- **行动指引缺失**：大量文章停留在科普层面，不回答"我该怎么做"——比如"血压 150/95 时该去急诊还是等预约？"
- **AI 搜索崛起**：越来越多用户通过 ChatGPT/Perplexity 提问健康问题，但 AI 引用的来源中，针对老年心血管群体的高质量站点极度稀缺

### 2.2 市场机会

| 信号 | 数据 |
|------|------|
| 核心关键词搜索量 | "exercise induced blood pressure" 单篇文章 90 天获得 947 次展示 |
| 月度增长趋势 | 展示量从 12 月 17 次 → 3 月 135 次，月均翻倍 |
| AI 搜索渗透 | GSC 出现 "bp ai"、"bp rating ai" 等查询词，用户正在尝试用 AI 理解健康数据 |
| 内容缺口 | 胆固醇方向仅 8 篇文章 vs 11+ 个搜索需求；热敏感与血压关联 3 个独立搜索词 0 内容承接 |
| 竞品盲区 | 竞品未系统覆盖"气候-心血管"、"宠物-心脏健康"、"AI工具-血压管理"等新兴方向 |

## 4. Core Strategy: The Flywheel

整个系统的核心逻辑是一个**数据驱动的内容飞轮**：

```
        ┌───────────────────────────┐
        │   Google Search Console   │
        │   (真实搜索数据)           │
        └────────────┬──────────────┘
                     │ 每天自动拉取
                     ▼
        ┌───────────────────────────┐
        │   趋势检测 + 缺口分析      │
        │   (哪些问题没人答？)        │
        └────────────┬──────────────┘
                     │ 转化为选题
                     ▼
        ┌───────────────────────────┐
        │   AI 自动生成文章           │
        │   (GEO 结构 + SEO 优化)    │
        └────────────┬──────────────┘
                     │ 自动发布
                     ▼
        ┌───────────────────────────┐
        │   Google 收录 + 排名        │
        │   → 更多搜索数据回流        │──────┐
        └───────────────────────────┘      │
                     ▲                      │
                     └──────────────────────┘
                       飞轮：数据 → 内容 → 排名 → 更多数据
```

**为什么这个飞轮有效？**

1. **数据优势**：我们不猜测用户想要什么，GSC 告诉我们用户在搜什么、什么排名在上升、什么内容有展示但没点击
2. **速度优势**：从发现趋势到文章上线 < 48 小时（紧急选题路径），竞品的人工编辑流程需要 1-2 周
3. **规模优势**：2,209 篇文章形成的 embedding 网络提供了强大的内链和去重能力，新文章一上线就嵌入整个知识图谱
4. **成本优势**：每篇文章成本 ~$0.04（Qwen API），全流程无人力介入

## 5. How It Works: Four Automated Workflows

### 5.1 Workflow A — 每日数据情报（08:00 Beijing Time）

**做什么**：从 Google Search Console 拉取最近 7 天的搜索数据，检测趋势异常。

**为什么这么做**：搜索趋势瞬息万变。某个关键词突然被大量搜索（如季节性变化导致"heat and blood pressure"飙升），我们需要在 24 小时内感知到并响应。

**核心逻辑**：
- 对比最近 3 天 vs 过去 28 天基线
- 检测三类异常：展示量暴涨（≥3 倍）、新出现的搜索词（连续 2 天以上）、排名跳升（≥10 位）
- 高分警报（score ≥ 50）自动转化为紧急选题，插入次日生成队列

**实际案例**："soup to lower cholesterol" 被检测为 RANK_JUMP 类型（score 54），自动生成选题，2 天内文章上线。

### 5.2 Workflow B — 每日文章生成（14:00 Beijing Time）

**做什么**：从选题库取 3-5 个选题，AI 生成文章，自动发布。

**为什么每天 3 篇而不是更多**：项目从高速扩张期（15-20 篇/天）进入成熟期。当前 2,209 篇文章中仅 6% 有搜索展示，盲目增加数量不如提升质量和优化已有内容。3 篇/天确保内容新鲜度，同时将资源倾斜到质量。

**内容结构（GEO 优化）**：
```
# H1 标题（含 Primary Keyword）
## Quick Answer（2-3 句直接回答，AI 系统可直接引用）
## Key Facts（5 个带数据的要点）
## ⚠️ When to See Your Doctor（具体阈值，如"收缩压 > 180 立即就医"）
## 深度解析（200+ 词，术语桥接："高血压(hypertension)"）
## 你能做什么（证据基础建议）
## FAQ（5 个问题，首句直接回答）
```

**为什么用这个结构**：
- **Quick Answer** → AI 搜索引擎偏爱可直接引用的简短答案段
- **Key Facts** → 结构化数据更容易被 AI 系统提取为 bullet points
- **术语桥接** → 同时匹配患者搜索词（"high blood pressure"）和医学术语（"hypertension"）
- **具体阈值** → E-E-A-T 信号，展示专业权威性

### 5.3 Workflow C — 每周选题更新（Saturday 09:00 Beijing Time）

**做什么**：汇总本周 GSC 数据 → LLM 深度分析 → Perplexity 竞品调研 → 生成 35 个新选题并评分排序。

**为什么分两层**：
- **Qwen LLM 分析**：看我们自己的数据（GSC），找到"高展示低点击"的文章（metadata 需优化）和"高需求低覆盖"的方向（需要新文章）
- **Perplexity 调研**：看外部世界（竞品在写什么、用户在问什么），发现我们的盲区

**选题评分机制（4 维度，总分 0-100）**：
| 维度 | 权重 | 逻辑 |
|------|------|------|
| 主题集群覆盖需求 | 30% | 某个 cluster 文章越少，分越高（填补缺口） |
| 搜索需求验证 | 25% | GSC 有真实搜索数据的选题得高分（不猜测） |
| 内容差异化 | 25% | 与已有 2,209 篇文章的 PK 重叠越低越好（避免内耗） |
| 时效性 | 20% | 上升趋势高分，下降趋势低分 |

### 5.4 Workflow D — 已有文章优化（按需执行）

**做什么**：根据 GSC 数据，优化已有文章的 Title、Description、Primary Keyword（不改正文）。

**为什么只改 metadata 不改正文**：
- 大多数"高展示低点击"的问题出在 metadata 上：标题不吸引人、描述没有回应搜索意图
- Metadata 修改成本极低（几秒/篇），效果可以在 7-14 天内通过 GSC 验证
- 正文已经过质量把关，问题不在内容深度，而在搜索结果页的"第一印象"

**已完成**：2,202 篇文章的 metadata 已按 v3.0 标准全量优化（GEO 优先 + SEO）。

## 6. Technical Architecture

### 6.1 技术栈

| 层 | 技术选型 | 为什么选它 |
|----|---------|-----------|
| 前端 | Next.js 14 (App Router) + Tailwind | SSG 生成静态页面，对 SEO 友好；Vercel 边缘部署，全球加载快 |
| 内容格式 | Markdown + YAML frontmatter | 轻量、Git 可追踪、无数据库依赖、LLM 容易生成 |
| LLM | Qwen Plus (Alibaba) | 成本极低（$0.04/篇）、中英文双语强、API 稳定 |
| 竞品调研 | Perplexity API (Sonar) | 直接返回带来源的搜索结果，比自己爬更准更快 |
| 搜索数据 | Google Search Console API | 唯一可信的搜索表现数据源 |
| 向量引擎 | Qwen Embedding + 本地 JSON | 支持 2,209 篇文章的相似度计算、去重、内链 |
| CI/CD | GitHub Actions + Vercel | 全自动：生成 → commit → push → 部署，零人工 |
| 部署 | Vercel (Serverless) | 免费额度充足，CDN 全球分发，自动 HTTPS |

### 6.2 成本结构

| 项目 | 月成本 |
|------|-------|
| Qwen API（文章生成 + 选题 + 分析） | ~$6 |
| Perplexity API（每周竞品调研） | ~$2 |
| Vercel 部署 | $0（免费额度内） |
| GitHub Actions | $0（免费额度内） |
| Google Search Console | $0（免费） |
| 人工运维 | $0（全自动） |
| **月总计** | **~$8** |

### 6.3 关键技术能力

**内容去重（两级检查）**：
- Level 1: Metadata 去重 — Primary Keyword 和 Title 的文本相似度 > 0.80 则拒绝
- Level 2: Content 去重 — 全文 Embedding 相似度 > 0.85 则拒绝
- **为什么重要**：防止内容自相蚕食（cannibalization），2,209 篇文章规模下没有去重会严重伤害 SEO

**智能内链（Embedding-based）**：
- 每篇文章生成向量 embedding
- 余弦相似度找最相关的 3-5 篇文章
- 双向链接（A→B 且 B→A）
- 每周自动重算全站内链
- **为什么重要**：内链结构直接影响 Google 爬虫的页面发现效率和权重传递

**YAML 安全写入**：
- 所有 metadata 使用 `>-` YAML 折叠格式写入
- **为什么**：经历过 62 篇 YAML 解析失败 + 3 次部署失败的教训，引号转义是 YAML 的天坑

## 7. Content Strategy: What We Write and Why

### 7.1 主题矩阵（6 大核心方向）

| 方向 | 优先级 | 当前文章数 | GSC 信号 | 策略 |
|------|--------|-----------|---------|------|
| Blood Pressure | P3 | 476+ | 强（exercise-induced BP 947 展示） | 长尾深耕，场景化（季节、运动、药物交互） |
| Diabetes / HbA1c | P1 | 中等 | 强（A1C goals 306 展示） | 大力扩展，老年糖尿病管理是最大流量机会 |
| Cholesterol | P1 | 仅 8 篇 | 中（11 个搜索需求） | 最大缺口，需快速补充 |
| Nutrition & Diet | P2 | 中等 | 中（fiber 30 展示，soups 22） | 场景化食谱：降胆固醇汤、高纤维配菜 |
| Exercise for Seniors | P1 | 中等 | 极强（947 展示） | 已有优势文章，扩展长尾（关节炎运动、椅子运动） |
| Heart Health | P3 | 中等 | 中 | 持续优化，宠物+心脏、气候+心脏等差异化角度 |

### 7.2 GEO（Generative Engine Optimization）策略

**这是什么**：针对 AI 搜索引擎（ChatGPT、Perplexity、Gemini）的内容优化，让我们的文章被 AI 引用为回答来源。

**为什么重要**：
- AI 搜索正在分流 Google 的传统搜索流量
- 当用户问 "What's the best app to track blood pressure for seniors?" 时，AI 会从网上抓取来源
- 如果我们的内容结构化程度高、权威性强，被引用的概率就大
- 一次 AI 引用 = 直接流量 + 品牌曝光 + 信任背书

**具体做法**：
1. **Quick Answer 段落**：每篇文章开头 2-3 句直接回答标题问题，AI 系统可以直接提取
2. **Key Facts Box**：结构化的 bullet points + 数据点，AI 最爱引用这种格式
3. **术语桥接**：同时包含患者语言和医学术语，覆盖两种搜索方式
4. **权威引用**：引用 AHA、ACC、NIH 等指南，增加 E-E-A-T 信号
5. **FAQ 结构**：直接对应 AI 搜索中的"follow-up questions"

### 7.3 30 条 GEO 测试问题

我们已设计 30 条专门测试 AI 搜索引用的问题（覆盖直接推荐、带读数求助、功能场景、设备集成、对比决策 5 个类别），用于持续监测我们的内容在 ChatGPT 和 Gemini 中的引用表现。

## 12. Why This Approach Works

**1. 数据驱动，不靠猜测**
每一篇新文章的选题都来自真实的 GSC 搜索数据或 Perplexity 竞品分析。我们不猜用户想看什么——数据告诉我们用户在搜什么。

**2. 速度碾压人工**
从发现搜索趋势到文章上线 < 48 小时。传统健康内容团队需要 1-2 周（选题会议 → 写作 → 编审 → 发布）。

**3. 规模构建壁垒**
2,209 篇文章 + 全站 embedding 网络 = 任何新进入者需要数月才能复制的内容规模。内链网络让每篇新文章都从整个知识图谱中获得权重加持。

**4. 双轨曝光**
同时优化 Google SEO 和 AI GEO。Google 算法变了，AI 引用兜底；AI 引用减少了，Google 流量补位。不把鸡蛋放在一个篮子里。

**5. 成本结构不可思议**
