## 二、Line 1 — 每日 GSC 数据线（gsc-daily-analysis.ts）

```
╔═══════════════════════════════════════════════════════════════════════════╗
║  每日运行 · 入口: scripts/gsc-daily-analysis.ts                          ║
╚═══════════════════════════════════════════════════════════════════════════╝

  ┌─────────────────────────────────────────────────────┐
  │  STEP 1: GSC 数据拉取                                │
  │                                                       │
  │  Google Search Console API                            │
  │  ├─ 时间窗口: today-9天 ~ today-3天 (GSC有3天延迟)    │
  │  ├─ 维度1: query (搜索词, 最多25000条)                │
  │  ├─ 维度2: page  (页面, 最多25000条)                  │
  │  └─ 字段: impressions, clicks, ctr, position          │
  │                                                       │
  │  输出 ──▶ data/seo/raw/{YYYY-MM-DD}.json              │
  │          (每天一个文件, 同日期覆盖)                     │
  └───────────────────────┬───────────────────────────────┘
                          │
                          ▼
  ┌─────────────────────────────────────────────────────┐
  │  STEP 2: 趋势检测                                     │
  │                                                       │
  │  对比: 最近3天数据 vs 28天基线                          │
  │                                                       │
  │  检测3种警报类型:                                       │
  │  ┌──────────┬──────────────────────┬───────────────┐  │
  │  │ 类型      │ 触发条件              │ 评分公式       │  │
  │  ├──────────┼──────────────────────┼───────────────┤  │
  │  │ SURGE    │ 展示量突增 ≥3倍基线   │ ratio×15      │  │
  │  │          │                      │ (上限100)     │  │
  │  ├──────────┼──────────────────────┼───────────────┤  │
  │  │ NEW_QUERY│ 新词连续出现≥2天      │ 展示×10       │  │
  │  │          │                      │ (上限60)      │  │
  │  ├──────────┼──────────────────────┼───────────────┤  │
  │  │ RANK_JUMP│ 排名提升≥10位        │ 提升位×3      │  │
  │  │          │                      │ (上限80)      │  │
  │  └──────────┴──────────────────────┴───────────────┘  │
  │                                                       │
  │  输出 ──▶ data/seo/analysis/daily-{date}.json          │
  └───────────────────────┬───────────────────────────────┘
                          │
                          ▼
  ┌─────────────────────────────────────────────────────┐
  │  STEP 3: 高分警报 → 紧急选题                           │
  │                                                       │
  │  筛选: score ≥ 50 的警报 (最多取3个)                   │
  │                                                       │
  │  对每个高分警报:                                       │
  │                                                       │
  │  ┌───────────────────────────────────────────────┐    │
  │  │  3a. Perplexity API 调用 🔍                    │    │
  │  │                                                │    │
  │  │  输入: alert.query (如 "exercise blood pressure")│   │
  │  │  模型: sonar (实时搜索)                         │    │
  │  │  温度: 0.2                                      │    │
  │  │                                                │    │
  │  │  返回:                                          │    │
  │  │  ├─ questions: 15个真实用户搜索问题              │    │
  │  │  ├─ competitorCoverage: 竞品都覆盖了什么         │    │
  │  │  └─ whyItMatters: 为什么现在火                  │    │
  │  └────────────────────┬──────────────────────────┘    │
  │                       │                               │
  │                       ▼                               │
  │  ┌───────────────────────────────────────────────┐    │
  │  │  3b. Qwen LLM 转化选题                        │    │
  │  │                                                │    │
  │  │  输入:                                          │    │
  │  │  ├─ alert.query + impressions + position       │    │
  │  │  ├─ alert.type + reason                        │    │
  │  │  └─ Perplexity发现的问题列表 (前5个)            │    │
  │  │                                                │    │
  │  │  输出:                                          │    │
  │  │  ├─ title                                      │    │
  │  │  ├─ primaryKeyword                             │    │
  │  │  ├─ description                                │    │
  │  │  ├─ topicCluster                               │    │
  │  │  └─ reasoning (为什么值得写)                    │    │
  │  └────────────────────┬──────────────────────────┘    │
  │                       │                               │
  │                       ▼                               │
  │  ┌───────────────────────────────────────────────┐    │
  │  │  3c. Embedding 去重                            │    │
  │  │                                                │    │
  │  │  生成embedding → 与2209篇已有文章对比            │    │
  │  │  阈值: > 0.80 = 太相似, 拒绝                    │    │
  │  │        ≤ 0.80 = 接受, 写入紧急选题               │    │
  │  └────────────────────┬──────────────────────────┘    │
  │                       │                               │
  │                       ▼                               │
  │  写入 ──▶ data/seo/urgent-topics.json                 │
  │           ├─ 1-3个紧急选题                             │
  │           ├─ 3天后自动过期 (expiresAt)                 │
  │           └─ 包含Perplexity问题 (perplexityQuestions) │
  └─────────────────────────────────────────────────────┘
```

## 三、Line 2 — 每周策略线（weekly-topic-refresh.ts）

```
╔═══════════════════════════════════════════════════════════════════════════╗
║  每周运行 · 入口: scripts/weekly-topic-refresh.ts                        ║
╚═══════════════════════════════════════════════════════════════════════════╝

  ┌─────────────────────────────────────────────────────┐
  │  STEP 1: 盘点现有选题库存                              │
  │                                                       │
  │  扫描 data/planned-topics-*.json                      │
  │  ├─ blood-pressure: 24个                              │
  │  ├─ diabetes: 18个                                    │
  │  ├─ heart-health: 32个                                │
  │  ├─ healthy-eating: 28个                              │
  │  ├─ exercise: 21个                                    │
  │  └─ cholesterol: 19个                                 │
  │                                                       │
  │  保留: score ≥ 30 的旧选题                              │
  │  淘汰: score < 30 的旧选题                              │
  │  目标: 本周生成 35个新选题                               │
  └───────────────────────┬───────────────────────────────┘
                          │
                          ▼
  ┌─────────────────────────────────────────────────────┐
  │  STEP 2: 汇总 GSC 周数据                               │
  │                                                       │
  │  加载 data/seo/raw/ 最近7天文件                        │
  │  ├─ 汇总搜索词 (按impression排序)                     │
  │  ├─ 汇总页面表现 (Top 20)                              │
  │  └─ 计算周趋势                                        │
  └───────────────────────┬───────────────────────────────┘
                          │
                          ▼
  ┌─────────────────────────────────────────────────────┐
  │  STEP 3: LLM 深度分析 (Qwen Plus)                     │
  │                                                       │
  │  输入: 搜索词列表 + Top页面 + 月度趋势 + 当前选题库     │
  │                                                       │
  │  输出:                                                │
  │  ├─ searchIntentAnalysis: 搜索意图分布分析              │
  │  ├─ ctrAnomalies: 高展示低CTR异常文章                  │
  │  ├─ hiddenOpportunities: 未覆盖的长尾机会              │
  │  ├─ topicPriorities: TOP 5推荐选题方向                 │
  │  └─ articleOptimizations: 需优化的现有文章              │
  │     (建议新title/description)                         │
  └───────────────────────┬───────────────────────────────┘
                          │
                          ▼
  ┌─────────────────────────────────────────────────────┐
  │  STEP 4: Perplexity 深挖真实需求 🔍                    │
  │                                                       │
  │  只对 P1/P2 优先级方向调用 (节省API成本)                │
  │                                                       │
  │  FOR EACH P1/P2 核心方向:                              │
  │  │                                                    │
  │  │  discoverUserQuestions(keyword, existingArticles)   │
  │  │  ├─ 模型: sonar (实时搜索)                          │
  │  │  ├─ 输入: 核心关键词 + 已有文章标题(避免重复)        │
  │  │  │                                                  │
  │  │  └─ 返回:                                           │
  │  │     ├─ 15个真实搜索问题                              │
  │  │     ├─ 竞品覆盖分析                                 │
  │  │     └─ 趋势原因                                     │
  │  │                                                    │
  │  核心方向 (automation-config.json):                    │
  │  ├─ P1: diabetes, cholesterol        (高优先级)        │
  │  ├─ P2: exercise, heart-health       (中优先级)        │
  │  └─ P3: healthy-eating, blood-pressure (低优先级, 不调) │
  └───────────────────────┬───────────────────────────────┘
                          │
                          ▼
  ┌─────────────────────────────────────────────────────┐
  │  STEP 5: 生成新选题候选 (Qwen Plus)                    │
  │                                                       │
  │  ★ 关键: Perplexity数据注入到angles中                  │
  │                                                       │
  │  原始angles (来自config):                              │
  │  ├─ "hba1c targets for elderly"                       │
  │  ├─ "blood sugar monitoring"                          │
  │  └─ ...                                               │
  │                                                       │
  │  注入后的 enrichedAngles:                               │
  │  ├─ "hba1c targets for elderly"         (原始)         │
  │  ├─ "blood sugar monitoring"            (原始)         │
  │  ├─ Real user search: "Is 150 mg/dL     (Perplexity)  │
  │  │   blood sugar dangerous at age 70?"                │
  │  ├─ Real user search: "Can Type 2       (Perplexity)  │
  │  │   diabetes be reversed in older adults?"           │
  │  ├─ ... (最多注入8个问题)                               │
  │  ├─ Competitor insight: "竞品覆盖了..."  (Perplexity)  │
  │  └─ Trending context: "为什么重要..."    (Perplexity)  │
  │                                                       │
  │  生成量按优先级分配:                                    │
  │  ├─ P1方向: 50% (约17个)                               │
  │  ├─ P2方向: 30% (约10个)                               │
  │  └─ P3方向: 20% (约8个)                                │
  │                                                       │
  │  总计生成: ~35个候选选题                                │
  └───────────────────────┬───────────────────────────────┘
                          │
                          ▼
  ┌─────────────────────────────────────────────────────┐
  │  STEP 6: 评分排序 (topic-scorer.ts · Scoring v2.1)    │
  │                                                       │
  │  四维评分模型 (总分0-100):                              │
  │                                                       │
  │  ┌──────────────────────────────────────────────────┐ │
  │  │                                                  │ │
  │  │  clusterNeed (0-30分)                            │ │
  │  │  该方向还缺多少文章?                               │ │
  │  │  ├─ 覆盖率<50% → 25-30分                         │ │
  │  │  ├─ 覆盖率<80% → 15-24分                         │ │
  │  │  └─ 近7天该方向已出3篇+ → 减8分(防轰炸)           │ │
  │  │                                                  │ │
  │  │  searchDemand (0-25分)                           │ │
  │  │  GSC中有没有人搜这个?                               │ │
  │  │  ├─ 精确匹配+10+展示 → 18-21分                    │ │
  │  │  ├─ 方向匹配+5+展示 → 10-15分                     │ │
  │  │  └─ 无GSC数据(纯LLM生成) → 4-12分                │ │
  │  │                                                  │ │
  │  │  differentiation (0-25分)                        │ │
  │  │  和已有文章有多不同?                               │ │
  │  │  ├─ PK重叠≤30% → 22-25分 (高度差异化)            │ │
  │  │  ├─ PK重叠30-50% → 15-24分                       │ │
  │  │  └─ PK重叠>70% → 2分 (有蚕食风险)                │ │
  │  │                                                  │ │
  │  │  timeliness (0-20分)                             │ │
  │  │  这个话题现在热不热?                               │ │
  │  │  ├─ GSC趋势上升中 → 16分                          │ │
  │  │  ├─ 突发趋势选题 → 19分 (最高)                    │ │
  │  │  └─ 常青内容 → 6分                                │ │
  │  │                                                  │ │
  │  └──────────────────────────────────────────────────┘ │
  │                                                       │
  │  排序后取 Top 35 写入选题库                             │
  └───────────────────────┬───────────────────────────────┘
                          │
                          ▼
  ┌─────────────────────────────────────────────────────┐
  │  STEP 7: 写入选题库 + 周报                             │
  │                                                       │
  │  更新文件:                                             │
  │  ├─ data/planned-topics-blood-pressure.json           │
  │  ├─ data/planned-topics-diabetes.json                 │
  │  ├─ data/planned-topics-heart-health.json             │
  │  ├─ data/planned-topics-healthy-eating.json           │
  │  ├─ data/planned-topics-exercise.json                 │
  │  └─ data/planned-topics-cholesterol.json              │
  │                                                       │
  │  每个文件 = 保留的高分旧选题 + 新生成的选题              │
  │                                                       │
  │  周报 ──▶ data/seo/analysis/weekly-{week}.json         │
  │  ├─ Perplexity insights (每方向)                      │
  │  ├─ Top 10 评分选题                                    │
  │  └─ 文章优化建议                                       │
  └─────────────────────────────────────────────────────┘
```

## 四、Line 3 — 每日生产线（auto-generate-daily.ts）

```
╔═══════════════════════════════════════════════════════════════════════════╗
║  每日运行 · 入口: scripts/auto-generate-daily.ts                         ║
╚═══════════════════════════════════════════════════════════════════════════╝

  ┌─────────────────────────────────────────────────────┐
  │  STEP 1: 确定今日生产目标                              │
  │                                                       │
  │  基于 automation-config.json:                         │
  │  ├─ Day 1-20:   15篇/天 (初始增长期)                  │
  │  ├─ Day 21-40:  20篇/天 (加速期)                      │
  │  └─ Day 41+:     5篇/天 (成熟期, 当前阶段)            │
  │                                                       │
  │  当前: Day 125+ → 目标5篇                              │
  └───────────────────────┬───────────────────────────────┘
                          │
                          ▼
  ┌─────────────────────────────────────────────────────┐
  │  STEP 2: 选题库存检查                                  │
  │                                                       │
  │  getTotalTopicsCount()                                │
  │  ├─ ≥ 30个选题 → 跳到STEP 3                           │
  │  └─ < 30个选题 → 触发紧急补充                          │
  │                                                       │
  │     紧急补充流程 (replenishMultipleTopics):             │
  │     ├─ 按库存从低到高排序各方向                         │
  │     ├─ 目标补充50个                                    │
  │     ├─ 每个方向最多补20个                               │
  │     └─ Qwen生成候选 → Embedding去重(阈值0.85)          │
  │        → 写入planned-topics-*.json                    │
  └───────────────────────┬───────────────────────────────┘
                          │
                          ▼
  ┌─────────────────────────────────────────────────────┐
  │  STEP 3: 构建今日选题池                                │
  │                                                       │
  │  两个来源合并:                                         │
  │                                                       │
  │  ┌─ 紧急选题 (优先级最高) ────────────────────────┐    │
  │  │  读取 data/seo/urgent-topics.json              │    │
  │  │  ├─ 过滤: 未过期 (expiresAt > now)             │    │
  │  │  ├─ 过滤: score ≥ 50                           │    │
  │  │  └─ 通常 0-3个                                 │    │
  │  └────────────────────────────────────────────────┘    │
  │                                                       │
  │  ┌─ 常规选题 (补齐剩余名额) ─────────────────────┐    │
  │  │  selectRandomTopicsForGeneration(count + 3)    │    │
  │  │  ├─ 从所有 planned-topics-*.json 读取          │    │
  │  │  ├─ 按 score 降序排列                          │    │
  │  │  ├─ 多样性约束: 同cluster最多2个连续            │    │
  │  │  └─ 多取3个备选 (防去重失败)                    │    │
  │  └────────────────────────────────────────────────┘    │
  │                                                       │
  │  最终选题池 = [紧急] + [常规], 优先消耗紧急选题         │
  └───────────────────────┬───────────────────────────────┘
                          │
                          ▼
  ┌─────────────────────────────────────────────────────┐
  │  STEP 4-8: 逐篇生成文章 (循环直到达标)                 │
  │                                                       │
  │  FOR EACH topic IN 选题池:                             │
  │    IF 已生成数 ≥ 目标数 → BREAK                        │
  │                                                       │
  │  ┌──────────────────────────────────────────────┐     │
  │  │  4. 生成文章正文 (Qwen Plus)                   │     │
  │  │     ├─ 模型: qwen-plus-latest, 温度0.7        │     │
  │  │     ├─ 结构: H1 → 快速答案 → 关键事实          │     │
  │  │     │        → H2×3 → FAQ×5 → 结论            │     │
  │  │     ├─ 字数: 1200-1800字                       │     │
  │  │     ├─ GEO: AI可引用陈述 + 医学指南引用         │     │
  │  │     └─ SEO: PK使用4-6次 + 3-5同义词             │     │
  │  └──────────────┬───────────────────────────────┘     │
  │                 ▼                                      │
  │  ┌──────────────────────────────────────────────┐     │
  │  │  5. Metadata优化 (Qwen Plus)                   │     │
  │  │     ├─ 基于正文前2000字优化                     │     │
  │  │     ├─ 温度: 0.3 (低创意, 高准确)               │     │
  │  │     ├─ 输出: title + pk + description + slug   │     │
  │  │     ├─ 重试: 最多2次                            │     │
  │  │     └─ 降级: 失败则用原始topic数据               │     │
  │  └──────────────┬───────────────────────────────┘     │
  │                 ▼                                      │
  │  ┌──────────────────────────────────────────────┐     │
  │  │  6. Embedding去重检查                          │     │
  │  │     ├─ 生成embedding (Qwen text-embedding-v4) │     │
  │  │     ├─ 与所有已发布文章对比余弦相似度            │     │
  │  │     │                                          │     │
  │  │     ├─ sim ≤ 0.80 → ✅ 通过                    │     │
  │  │     └─ sim > 0.80 → ⚠️ 太相似                  │     │
  │  │         ├─ 换角度重新生成正文+metadata           │     │
  │  │         ├─ 再次去重                             │     │
  │  │         ├─ 通过 → ✅ 接受                       │     │
  │  │         └─ 仍不通过 → ❌ 放弃, 取下一个选题     │     │
  │  └──────────────┬───────────────────────────────┘     │
  │                 ▼                                      │
  │  ┌──────────────────────────────────────────────┐     │
  │  │  7. 智能内链                                    │     │
  │  │     ├─ 找相似文章 (sim ≥ 0.50, Top 5)          │     │
  │  │     ├─ 新文章 → relatedSlugs = [前3-5篇]       │     │
```

## 七、关键阈值速查表

| 参数 | 值 | 所在环节 |
|------|-----|---------|
| GSC警报触发分 | ≥ 50 | 紧急选题筛选 |
| SURGE倍数 | ≥ 3x基线 | 趋势检测 |
| 紧急选题过期 | 3天 | urgent-topics生命周期 |
| 选题去重阈值 | 0.85 | 选题补充 |
| 文章去重阈值 | 0.80 | 文章生成 |
| 内链推荐阈值 | 0.50 | 智能内链 |
| 选题库最低库存 | 30个 | 触发紧急补充 |
| 每周新生成选题 | 35个 | 周度刷新 |
| 每次补充上限 | 50个 | 紧急补充 |
| Embedding维度 | 1024 | Qwen text-embedding-v4 |

## 八、外部依赖

| 服务 | 用途 | 调用频率 |
|------|------|---------|
| **Google Search Console API** | 搜索数据拉取 | 每日1次 |

| **Qwen text-embedding-v4** | 语义去重、内链推荐 | 每日10-50次 |
| **GitHub Actions** | 自动化调度 | 每日1次 (cron暂停中) |
| **Vercel** | 自动部署 | 每次push自动触发 |
